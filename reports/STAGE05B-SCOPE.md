# Stage 05B 范围与锁定信息架构

日期：2026-09-20
前提：Stage 05A 设计方向已确认通过。本阶段不重构已确认工作台。

## 1. 当前锁定的页面结构

### 学生工作台（锁定，不再大改）

```text
顶栏：课程/任务 · 连接 · 保存状态 · 运行检查 · 提交入口
左栏：任务目标、六阶段、本阶段验收
中栏：文件树、Monaco、运行结果 / 验收 / 成果预览
右栏：当前观察、证据、本轮指导、学生观察、下一步
Evidence Drawer：教学结论 → 原因说明 → 技术追溯 → 有界原始输出
```

三栏结构、教练信息层级、Evidence Drawer 顺序保持不变。05B 只增加顶栏「提交」入口，进入独立提交/复盘页，不拆工作台。

### 教师课堂台（锁定，不再大改）

```text
顶栏：课堂上下文 · 自动更新
左：需要关注 / 进行中 / 已完成
右：详情 tabs（概览 / 证据 / 轨迹）+ 介入操作区
Evidence Drawer 复用学生端同一信息层级
```

列表 + 详情区 + tabs + 介入操作区保持不变。05B 只在详情中增加「评价作品」入口，进入独立评价页。

### Evidence Drawer（锁定）

1. 教学结论（满足 / 未满足，绑定 Snapshot）
2. 为什么得到这个结论
3. 技术追溯（工具、原因代码、时间）
4. 有界原始输出

不把 Drawer 改成聊天、表格或评分表。

## 2. Stage 05B 功能范围

只做 FAQ-001-v1 的提交、复盘与教师确认成绩。

| 做 | 不做 |
|---|---|
| 学生把指定 Snapshot 冻成提交；同 Snapshot / 同 operation_id 幂等 | 重构工作台或课堂台 |
| 学生复盘页：自动检查 / AI 建议 / 教师确认分栏 | 任务设计器、成效中心、匿名导出 |
| 教师评价页：左作品/检查/解释/变式，右量规 | 另一套视觉语言 |
| 未填项保持「待评价」，不用 0 或满分占位 | 提示次数扣分 |
| 正式成绩只在教师发布后写入；AI 建议不能成为分数 | 模型或 Graph 写 `formal_grade` |
| `TEACHER_REVIEW` 由教师确认写入，绑定提交 Snapshot | 隐藏测试进入学生目录 |
| 课堂「需要关注」增加提交待复核 | 完整移动 IDE、其他课程 |

量规（课程任务，不是比赛评分）：功能与边界测试 40、调试解释 25、方案与迁移 20、规范与协作 15。

提交后学生仍可继续编辑；评价始终针对被提交的 Snapshot，不用后续编辑冒充已交版本。
