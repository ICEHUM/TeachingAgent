# 智训工坊 · 阶段 04 三题与智能体职责验收

日期：2026-09-24
状态：本地 DEMO 环境已完成三道 Python 基础练习的真实 Runner 与业务 API 验收；界面信息架构的全面收敛属于阶段 05。

## 本阶段交付

- 服务端固定 `PYB-01` 两数相加、`PYB-02` 判断是否及格、`PYB-03` 遍历列表求和三个 `v1` 任务包。每题有题面、起始代码、公开与隐藏用例、两项验收定义、教师量规及技能标识。隐藏输入和预期输出不进入学生工作区或 Docker 命令。
- 三题都走同一个 Docker Python Runner、Snapshot、LangGraph 与 RequirementResult 流程。服务端按任务版本选固定任务包和工具权限，任务版本数据库 JSON 不能扩张执行权限；旧 FAQ 仍走 OpenHands 回归路径。
- 公开检查对每个样例保存实际与预期输出、可观察的错误分类，以及 `verified_in_sample` / `needs_review` 技能证据。它只描述这一次样例，不推断 0–100 掌握度。提交时隐藏检查只返回汇总通过状态。
- `PYB-02` 公开检查要求实际使用 `if/else`；`PYB-03` 要求实际用 `for` 遍历 `numbers`。结构检查只解析 AST，不在宿主执行学生代码。
- 教师分析助手的数据库上下文与响应来源增加按题汇总的公开检查人数与技能 ID，并约束模型不得将其表述为掌握度；课堂结论仍可下钻到学生 RequirementResult 和证据。学生登录仍默认进入 PYB-01，任务栏可切换三道 Python 练习，并保留切换前的未保存代码。

## 四项可观察职责

| 职责 | 本地可核对的行为 | 权限边界 |
| --- | --- | --- |
| Guard | 固定任务包、工具白名单、Snapshot 归属、Docker 隔离和隐藏用例脱敏 | 不让浏览器或模型决定可执行工具 |
| Assessment | 公开/隐藏检查、结构要求、RequirementResult 与样例级技能证据 | 测试结果决定客观状态，正式成绩仍由教师确认 |
| Tutor | 根据当前 Snapshot、公开检查、学生观察和历史提示生成 L0/L1/L2 下一步；模型失败使用可说明的保底提示 | 不提供完整答案、隐藏用例或自动改码 |
| Teaching Insight | 根据真实 DEMO 业务记录汇总课堂状态和各题公开检查证据，供教师对话与下钻 | 示例数据明确标记，不宣称真实教学成效或能力评分 |
