# AI应用开发实训教练功能设计文档

版本 2.0　更新日期 2026年9月20日

本文是供项目负责人、前后端开发和试用教师共同使用的开发设计基线。方案采用 LangGraph 统一管理教学流程，OpenHands SDK 与 Agent Server 承担范围明确的实训执行，DeepSeek 提供诊断与反馈，学生和教师通过网页使用系统。本版替代 v1 的框架方案，保留已确认的课程定位、双端界面与分层指导目标。

## 1 项目定位与交付范围

用户已确认：服务高职人工智能技术应用专业，首期课程为 AI 应用开发实训，学生已具备 Python 基础。参赛方向为职业院校赛道、高职层次、实践教学与实训智能体。首个拟开发任务为“构建带来源引用的 FAQ 问答服务”，采用教师自编或获授权的示例资料。

产品帮助学生在真实代码与运行环境中完成任务，提供与当前困难相匹配的指导，并帮助教师依据作品、解释和独立测评作出评价。首轮访谈需核实学生调试困难、答案依赖和教师重复指导负担，不预先把这些假设写成已证实的教学现象。

首版交付一个完整教学任务及师生使用链路：教师配置与发布，学生进入独立工作区、编辑和测试，系统分层指导，教师介入，学生提交，教师复核，形成脱敏过程记录。语音、数字人、跨校管理及复杂知识图谱列为后续扩展。

本文件是内部功能设计文档，不是比赛要求的3000字以内建设说明书。申报材料需在真实试用后按赛事格式另行提炼。

## 2 本次架构调整

### 2.1 分层职责

| 层级 | 采用组件 | 负责内容 |
|---|---|---|
| 用户界面 | React与TypeScript | 学生实训台、教师课堂台、编辑与反馈、过程查看 |
| 业务入口 | FastAPI | 身份和资源授权、任务管理、请求校验、事件推送 |
| 教学控制 | LangGraph | 教学状态、条件分支、分层指导、等待与恢复、教师介入 |
| 模型服务 | DeepSeek接入适配器 | 根据给定证据生成诊断、提示和评价建议 |
| 实训执行 | OpenHands SDK与Agent Server | 读取工作区文件、执行指定检查、采集输出、处理受控改动 |
| 运行与存储 | Docker及数据库 | 独立工作区、运行资源、任务记录、检查点与提交快照 |

请求路径为：师生网页 → FastAPI → LangGraph教学流程 → 模型服务或实训工具 → 结构化结果 → 数据存储与网页反馈。发布任务、访问控制、正式成绩保存等确定性业务直接由业务服务处理，不必全部进入模型流程。

LangGraph 是流程编排运行时，不能自动提供课堂量规、账号授权或容器隔离。本项目需要实现这些业务规则，并为流程配置持久化检查点。OpenHands 首版作为执行接口使用，不再单独掌握一个无限循环的教学决策流程。

### 2.2 保留与新增

保留已经验证的 WSL2、Docker Desktop、OpenHands 1.49.2 工作区和 DeepSeek 接入配置。新增 LangGraph 教学控制、持久化状态、权限和任务服务、长任务管理、业务前端以及评价记录。模型适配器先复用现有接入经验，LangGraph 节点通过统一接口调用；保留已有用量字段兼容回归测试。

当前工作区模块已经验证短期容器的创建、命令执行、目录分离、认证及回收。正式网页需要另行实现跨请求的工作区会话管理、空闲回收与恢复；目前的上下文管理器不等同于完整课堂会话服务。

### 2.3 设计边界

教学状态以数据库中的任务尝试记录为准，LangGraph检查点保存流程恢复信息，二者以任务尝试ID和版本号关联。工具结果不能直接修改成绩或教学模式。前端展示教学步骤、证据与任务状态；容器ID、模型密钥和底层接口参数不进入师生操作界面。

## 4 用户角色与访问范围

| 角色 | 可执行操作 | 访问范围 |
|---|---|---|
| 学生 | 运行自己的任务、编辑代码、请求指导、提交和查看反馈 | 本人及明确授权的小组任务；首版以个人任务为主 |
| 授课教师 | 配置任务、查看过程、介入、复核与发布成绩 | 已分配的课程和班级 |
| 项目管理员 | 账号初始化、资源配置、故障维护、演示环境管理 | 运维授权范围；不因管理员身份默认改成绩 |
| 评审演示账号 | 按预设脚本体验学生或教师功能 | 独立示例课程和脱敏数据 |

正式系统根据登录账号确定角色，每次请求都校验角色、班级和对象归属。切换前端标签、猜测对象ID或使用其他学生的任务ID均不能获得权限。现有草图中的“学生端／教师端”切换仅用于预览设计。

## 5 页面结构与操作设计

### 5.1 学生端

学生端包括课程任务列表、实训工作台、提交与复盘三个主要页面。任务列表显示任务状态、截止信息和教师反馈，点击“继续实训”恢复本人最近的任务尝试。

实训工作台采用左中右布局。左侧显示任务书、能力目标、交付清单和阶段步骤；中间显示文件与代码，下方切换运行输出、测试结果和成果预览；右侧显示实训教练、指导依据与学生解释输入。顶部显示教学模式、保存状态和运行状态，主要操作为保存、运行检查、获取提示、求助教师和提交。

运行失败必须提供失败类型与可行下一步。排队时显示排队状态，准备时显示工作区正在启动；不能把模型请求失败显示成“学生回答错误”。编辑器恢复与提交均使用版本校验，遇到冲突保留双方版本并让用户选择，不能静默覆盖。

提交页展示将被提交的代码版本、验收情况、学生解释和系统内AI协助记录。复盘页分开呈现测试结论、AI反馈建议和教师确认，提供变式任务入口。

### 5.2 教师端

教师端包括任务设计、课堂工作台、作品评价、成效与材料四类页面。任务设计页先填写教学目标和成果要求，再配置材料、初始代码、测试、帮助策略和量规；发布前支持教师试跑与学生视角预览。

课堂工作台以学生阶段和可核对事件为主。提醒包含学生主动求助、同一测试反复失败、提交待复核等，触发阈值可配置。点击学生后查看近期代码差异、测试输出、提示历史和解释记录，教师可补充指导、调整帮助级别、暂停AI协助或发布共性问题说明。

作品评价页按量规逐项复核并显示证据链接，修改建议分值需保留教师理由。成效页面显示实际数据的口径、人数与任务版本，支持匿名导出；资源异常只作为课堂运行信息，不计入学生能力评价。

### 5.3 可用性要求

电脑浏览器承担主要编码操作；手机优先支持任务查看、反馈与求助。所有操作支持键盘访问，状态不用颜色单独表达。长时间等待应有阶段反馈和取消入口，页面刷新后能够根据服务端记录恢复状态。

## 6 功能需求与验收条件

P0表示首个真实课堂试用前必需，P1表示试用后增强。所有需求均属于待开发业务，现有运行环境验证不能替代下述验收。

### F01 登录与课程入口

P0。教师创建或导入本次试用所需账号，分配课程班级；学生登录后只看到分配的任务。演示账号使用独立数据空间。验收：两名学生不能读取对方文件和反馈，非任课教师不能修改该班任务，退出后受限接口拒绝访问。

### F02 实训任务设计与发布

P0。教师维护目标、材料、初始代码、测试、阶段条件、帮助策略和量规，任务发布后生成不可变版本。修改形成新版本，已开始任务继续绑定原版本或经教师明确迁移。验收：教师预览并试跑后发布，学生获得一致任务版本；已提交作品仍能追溯原验收条件。

### F03 独立实训工作台

P0。为每次任务尝试分配独立目录和工作区，支持文件编辑、自动保存、代码运行、指定测试、输出查看、取消和恢复。文件访问限制在本任务范围，运行过程受CPU、内存、时间和输出大小限制。验收：刷新不丢失已保存内容，超时可停止，另一学生看不到本工作区文件，回收容器后可从已保存目录恢复。

### F04 基于证据的分层指导

P0。收集当前任务要求、代码快照、测试输出、已给提示和学生解释，生成困难假设与帮助建议。L0追问思路，L1提供定位及概念提示，L2提供教师允许的局部示例。提示必须关联观察证据或课程资料；证据不足时先提出检查步骤，不编造报错原因或文件内容。

升级提示需满足教师策略，例如学生已记录观察、已尝试检查或教师主动调整。教师可以越过提示阶梯及时帮助，不能让机械流程阻碍学习。验收：相同错误在不同帮助权限下产生不同范围的反馈；无效输出进入重试或教师求助分支，绝不自动扩大工具权限。

### F05 教学模式与阶段控制

P0。支持引导练习、教师演示、独立考核三种模式。教师演示中的AI补丁必须先显示改动预览，经授权确认后应用到指定代码版本；普通练习默认由学生修改代码。独立考核在服务端关闭解题和改码能力，仅保留教师允许的非答案帮助。验收：改前端参数、提示词或重放旧请求不能切换模式；过期授权不能应用到新版本文件。

### F06 教师介入与恢复

P0。学生主动求助或满足教师设置的条件时创建介入事项，显示事实、已尝试操作和待解决问题。教师可补充提示、调整级别、说明下一步或结束本次指导。介入后从对应任务状态继续，记录处理人与理由。验收：等待期间释放流程执行线程；服务重启后待处理事项仍在，同一事项重复确认不会重复触发动作。

### F07 提交与学习复盘

P0。提交生成代码、任务版本、测试报告、解释和协助记录的快照，后续编辑产生新版本。记录学生修改、AI建议及已采纳补丁的来源，不能据此推断系统外AI使用。验收：重复提交请求只生成一个逻辑提交，教师能查看当时版本，学生能查看反馈并再次提交符合课程规则的版本。

### F08 评价复核与独立迁移

P0。自动测试给出可重复的功能结果，模型提供带证据的评价建议，教师按量规确认正式成绩。变式任务使用不同资料或边界条件，在教师设定的帮助范围内检查迁移能力。允许学生提出反馈或复核申请。验收：无有效证据的评价建议不能自动成为正式分数；评分修改保留版本和理由。

### F09 应用成效与任务复用

P0包含过程记录、基础汇总、脱敏CSV及证据索引导出；P1增加分组比较和更丰富的图表。记录实际参与人数、任务版本、前后测条件、教师复核结果和反馈。任务模板可复制，复制后明确材料授权及适用学情。验收：汇总数能回查原始记录，缺交和缺失数据有口径，示例数据不能混入真实课堂统计。

### F10 评审演示与材料整理

P0。提供独立可重置的演示课程、学生与教师测试账号、操作指引、匿名显示与脱敏导出。展示任务全过程以及开源组件与自研模块的边界。验收：从新的浏览器会话可按指引完成演示；页面、文件名和导出无非必要身份信息，原始审核材料与匿名评审材料分别管理。

## 7 LangGraph教学流程

### 7.1 状态与节点

每次任务尝试拥有独立的流程标识。流程状态至少包含任务尝试ID、任务版本、当前阶段、教学模式、策略版本、代码快照ID、证据引用、帮助级别、学生解释、待处理介入事项、执行任务ID和状态版本。模型密钥与工作区访问凭据不放入可返回前端的状态或检查点正文。

| 节点 | 输入 | 输出与下一步 |
|---|---|---|
| 接收事件 | 学生请求、测试完成或教师操作 | 校验身份、归属和事件版本 |
| 装载教学策略 | 任务版本、模式、教师调整 | 本轮允许动作与帮助范围 |
| 收集学习证据 | 文件快照、测试、解释 | 带来源的证据摘要 |
| 判断下一步 | 证据、历史与策略 | 继续检查、提示、等待、教师介入或验收建议 |
| 执行受限操作 | 经校验的工具请求 | 执行任务ID及结构化结果 |
| 生成指导 | 证据与允许的帮助级别 | 提示、引用和学生下一步操作 |
| 等待师生输入 | 需要解释或教师处理 | 保存检查点并暂停本次流程 |
| 阶段验收 | 测试、解释与教师量规 | 达标建议、缺项或人工复核 |
| 记录与返回 | 本轮动作及结果 | 保存过程事件并通知前端 |

流程允许根据新证据返回诊断或检查节点。每轮模型调用、工具调用和重试次数由后端设定上限，达到上限后返回可理解的状态或转教师处理。节点的短解释说明决策依据，不要求输出模型内部思维链。

### 7.2 等待与恢复

使用持久化checkpointer保存LangGraph状态，教师介入等等待可通过interrupt机制实现。恢复请求必须验证原任务归属、教师权限、待处理事项ID和状态版本，不能直接接受浏览器任意指定的流程标识。

恢复可能重新执行节点中的代码。写文件、创建容器、提交作品和发布评价均通过业务服务的操作ID去重；工具开始前写入执行记录，重试先查询该操作的结果。检查点恢复不自动回滚外部文件；需以代码快照和执行记录核对状态。

教师在等待期间修改策略后，恢复流程先重新检查最新权限及任务版本，再决定是否继续。已失效的补丁确认或评分操作要求重新审核，不能沿用旧授权。

### 7.3 错误与取消

模型超时、结构化结果不合法和工具失败分别记录，采用有上限的重试。前端取消请求后，后端标记取消并停止可中断任务；无法立即终止的操作显示正在停止，最终保存实际退出状态。无测试结果时显示未验证，不将无响应解释为通过。

## 8 OpenHands实训执行接口

首版将现有工作区能力封装为业务工具，所有调用经过身份、目录、模式和资源校验。学生提交的代码及其输出作为待分析数据，不能成为修改教师策略或访问宿主机的指令。

| 业务工具 | 主要输入 | 主要返回与限制 |
|---|---|---|
| 读取任务文件 | 工作区ID、相对路径、版本 | 文件内容或差异；禁止越出任务目录 |
| 运行指定检查 | 任务版本、代码快照、测试集ID | 退出状态、测试项、输出；命令由后端构造 |
| 运行学生程序 | 本人代码版本、允许的入口 | 日志与结果；只在本人受限容器内执行 |
| 获取执行结果 | 操作ID、事件位置 | 增量输出或终态；不可读取他人操作 |
| 提出与应用补丁 | 差异、目标版本、授权记录 | 改动预览或新版本；仅在允许模式执行 |
| 创建和回收工作区 | 任务尝试ID、资源配置 | 运行状态；只管理归属明确的容器与目录 |

Agent Server使用服务间凭据，浏览器不直接连接容器端口或获取其凭据。正式使用经FastAPI代理文件、运行和事件。每个容器仅挂载自己的任务目录，不挂载模型密钥和Docker socket。教师的参考答案及正式评分测试在学生不可修改的独立评价环境中执行。

实训任务若需要学生程序调用模型，提供限额的后端模型代理或预设响应夹具；学生程序不直接获得项目主密钥。是否开放联网、依赖安装及可用资源由任务策略规定，课堂部署需按测试结果配置相应隔离措施。

## 9 数据与接口设计

### 9.1 主要数据对象

| 对象 | 关键内容 | 一致性要求 |
|---|---|---|
| 用户与课程成员 | 用户、角色、课程、班级 | 每次对象访问按成员关系授权 |
| 任务版本与策略 | 材料、测试、量规、模式、帮助规则 | 发布版本不可变，调整留痕 |
| 任务尝试 | 学生、任务版本、阶段、状态版本 | 一个尝试关联独立流程与工作区 |
| 工作区与执行任务 | 目录、资源、操作ID、退出状态 | 重试去重，回收可追溯 |
| 指导与介入事件 | 证据、提示、解释、教师操作 | 区分事实、AI建议与人工决定 |
| 提交快照 | 文件版本、测试、解释、协助来源 | 提交后不被后续编辑替换 |
| 评价与复核 | 量规项、建议、教师确认、理由 | 正式成绩必须有确认主体 |
| 成效与导出 | 统计口径、样本、证据索引 | 原始数据、匿名数据和示例数据分开 |

单机试用使用SQLite保存业务数据，并配置匹配的LangGraph持久化检查点。多人并发部署前评估迁移PostgreSQL及持久任务队列。数据库迁移、备份恢复和版本升级需有脚本；检查点不能代替完整教学业务记录。

### 9.2 接口分组

| 接口分组 | 拟采用路径示例 | 主要语义 |
|---|---|---|
| 登录与课程 | /api/auth 与 /api/courses | 登录、会话、课程成员 |
| 任务管理 | /api/tasks 与 /api/task-versions | 编辑、发布、预览与版本查询 |
| 学生任务 | /api/attempts/{id} | 开始、恢复、阶段与策略查询 |
| 文件和运行 | /api/attempts/{id}/files 与 /runs | 版本编辑、启动运行、查询和取消 |
| 智能指导 | /api/attempts/{id}/guidance | 提交证据请求，返回指导事件 |
| 教师介入 | /api/interventions/{id} | 查看、处理及恢复关联流程 |
| 提交与评价 | /api/submissions 与 /reviews | 快照提交、复核、发布与反馈 |
| 事件与导出 | /api/attempts/{id}/events 与 /exports | SSE事件流及脱敏文件导出 |

以上为接口分组设计，实施时形成OpenAPI契约，明确请求体、返回体和错误码。长任务返回操作ID，前端通过SSE接收事件或按ID查询；断线后携带事件位置补读。鉴权失败、版本冲突、资源排队、模型失败和执行失败应有不同的用户提示。

## 10 首个实训任务与教学评价

首个任务让学生构建FAQ问答服务，提交可运行代码、带来源的回答、边界测试和调试解释。阶段依次为理解需求、准备资料、实现检索、生成带引用回答、验证边界并交付。教师提供有限规模的示例文档和初始代码，难度由实际学情调整。

课堂示例：学生程序读入资料但检索为空；系统依据运行结果引导学生检查问题处理与匹配条件；学生记录观察后修改并重测；教师查看共性错误并作针对性讲解。课末保存提交快照，课后更换资料或问题形式，在规定帮助条件下完成迁移任务。

经负责人确认，任务量规为功能与边界测试40分、调试解释25分、方案与迁移20分、工程规范与可复现性15分。第四项依据 `delivery_static_check`、`source_quality_review`、`delivery_review` 以及 README、交付文件和可复现说明进行评价。这是课程任务量规，不是比赛评分表。获得提示本身不直接扣分，独立能力由单独任务和教师复核评价。

## 11 成效采集与材料规范

试用前确定课程、实际人数、课时、基础水平、任务版本和评价口径。记录前后测及变式任务结果、任务达标情况、错误复发、教师重复指导耗时和师生反馈。教师登录时长不能代替教学耗时，AI修改比例不能直接代表学生掌握度。

若采用前后测或不同班级比较，说明帮助条件、任务难度、缺失数据及其他差异。每项统计可追溯到原始记录；页面示例和系统冒烟测试不能作为学习效果提升证据。推广价值通过模板复用、替换材料的过程和其他教师反馈逐步验证。

通知要求建设说明书不超过3000字、50M，附件5简介限1200字、应用成效限1800字；视频6至10分钟、720P及以上、MP4且不超过1200M。现场汇报不超过10分钟，提问5分钟。演示材料按匿名要求处理，提供可用测试入口与账号，原始审核材料与匿名评审材料分别管理。学校审核和盖章由参赛教师按要求办理，系统导出不代替该流程。

开源组件、自研教学规则、适配代码和开发记录分别说明。使用教师或学生数据前明确用途、访问范围、保留与删除方式；教师和学生只访问授权范围。附件5的应用安全证明注明“若有则勾选”，不把未提供的证明写成已经具备。

## 12 实现顺序与验收清单

### 12.1 分阶段实施

| 阶段 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| A 架构与契约 | LangGraph最小流程、数据模型、工具接口、模式策略 | 模拟事件可推进、暂停、恢复且不越权 |
| B 师生核心页面 | 学生工作台、教师任务发布与课堂台 | 通过真实接口完成发布、编辑、运行和查看 |
| C 教学完整链路 | 分层指导、教师介入、提交快照、评价复核 | 两名学生和一名教师完成同一任务全流程 |
| D 课堂试用与展示 | 真实数据采集、基础导出、匿名演示入口 | 故障恢复、并发和演示检查通过，证据来源清晰 |

页面可按已确认草图先实现，但最终验收使用真实后端和独立工作区。首个可用版本以P0功能为范围，P1在试用反馈后安排，不预设发布日期或教学提升幅度。

### 12.2 核心验收用例

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 教师发布版本化任务 | 学生领取同一版本，旧提交可回查原条件 |
| A02 | 两学生同时实训 | 目录、事件、评价与访问凭据相互隔离 |
| A03 | 连续错误后的提示 | 使用真实证据，按策略选择层级并记录依据 |
| A04 | 考核模式绕过尝试 | 前端参数和提示内容不能启用解题或改码工具 |
| A05 | 等待教师时服务重启 | 待处理事项和检查点可恢复，权限重新核验 |
| A06 | 重复请求与网络重试 | 不重复提交、不重复发布评价，不重复应用补丁 |
| A07 | 模型或工具失败 | 显示真实失败，保留已保存代码，支持有限重试 |
| A08 | 教师调整与旧授权 | 过期策略和不匹配代码版本不能继续执行 |
| A09 | 教师复核成绩 | 每项有依据，修改有理由，正式成绩可追溯 |
| A10 | 匿名演示和成效导出 | 新会话可使用，示例与真实数据分开，无非必要身份信息 |

运行性能在目标机器上测量。现有“两容器测试通过”仅说明基本可行，不能据此承诺全班并发。首轮默认从少量并发加排队开始，记录容器冷启动、运行时延、模型等待、CPU与内存峰值，再决定服务器配置和课堂规模。
