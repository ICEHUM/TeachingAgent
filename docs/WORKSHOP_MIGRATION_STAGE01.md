# 智训工坊改造 · 阶段 01 产品与任务基线

日期：2026-09-23
状态：首版实施基线；三道实验的教学文字与量规仍须任课教师在真实试用前核对。

## 1. 产品决策

- 以现有 `D:\TeachingAgent` 工程增量开发，不重新实现已跑通的师生端、证据链和教学流程。
- 首版只交付一门 **Python 基础编程** 课程与三项完整实验。另外两门课程待负责人提供教学材料后接入；任务与数据模型从首版起支持课程 ID 和任务版本。
- 学生闭环：读题 → 编辑并保存 → Run（运行程序及公开检查）→ 查看定位与证据 → 按需向 Tutor 求助 → 修改重试 → Submit（隐藏测试）→ 教师复核。
- 教师闭环：进入课堂 → 识别需要帮助的学生和共性卡点 → 查看对应运行证据与轨迹 → 对话分析并生成可交互图表 → 人工介入或确认成绩。
- Guard、Assessment、Tutor、Teaching Insight 是四项可观察的服务职责。Guard 和 Assessment 的客观判断由规则、测试和证据支撑；模型不能自行决定测试通过、正式成绩或权限。
- OpenHands 暂作执行过渡层。新 Runner 在隔离、限额、超时、公开/隐藏测试、结构化结果、证据绑定和故障降级全部通过后替换它；本阶段不移除依赖。
- FAQ 场景保留为旧版本回归材料，不再作为新版默认课程。演示虚拟数据与真实试用数据分别标记、存储和展示。

依据：`D:\AgentAI\智训工坊_自主研发版_开发设计文档_V1.0.docx`、`D:\AgentAI\智训工坊_MVP范围与验收基线_V0.1.md`；现有能力以代码为准，旧 `docs/functional-design-v2.md` 保留为历史设计。

## 2. 三项实验的首版题目

三题从**输入、变量和运算**开始，逐步加入**条件判断**与**遍历循环**。首版只要求学生补全单文件 Python 程序；不要求自行编写函数、处理 CSV、读取文件、使用字典或设计异常处理。题目是实施用的首版内容，不宣称来自真实课堂调研。正式试用前由任课教师核对题面、难度与预期用时。

| 任务 ID | 学生要完成的程序 | 核心技能 | Run 可见检查 | Submit 隐藏检查 |
| --- | --- | --- | --- | --- |
| PYB-01 两数相加 | 从两行输入读取整数，输出它们的和 | `input`、`int`、变量、`+`、`print` | 正整数、一个零 | 负数、两个零、较大的整数 |
| PYB-02 判断是否及格 | 从输入读取 0–100 分，输出“及格”或“不及格” | 比较、`if/else`、缩进 | 59 分、60 分 | 0 分、100 分及其他区间内分数 |
| PYB-03 遍历列表求和 | 系统已把输入整数放进 `numbers` 列表；学生用 `for` 遍历并输出总和 | 列表、`for`、累加变量、`print` | `[2, 3, 5]`、空列表 | 单个值、重复值、负数与不同长度列表 |

### 面向学生的题面与完成标准草案

**PYB-01：两数相加。**题面：“程序依次读取两行整数，只输出两数之和。例如输入 `2` 和 `3`，输出 `5`。”起始代码给出两行 `input()` 的位置，学生完成转换、运算和输出。运行时公开展示输入 `2, 3` 和 `0, 7` 的结果；提交时检查负数、两个零和较大整数。完成标准是每组输入都输出一个正确整数，没有额外提示文字。诊断可区分输入未转换、把数字拼接成字符串、输出格式多余。

**PYB-02：判断是否及格。**题面：“程序读取一行 0–100 的整数分数。分数大于或等于 60 时只输出 `及格`，否则只输出 `不及格`。”起始代码给出读取整数的第一行，学生补全 `if/else`。公开检查 59、60；隐藏检查 0、100 和其他合法分数，不要求处理范围外输入。完成标准是边界正确、缩进正确，且没有额外输出。诊断可区分语法/缩进错误、比较符号错误、输出文字不符。

**PYB-03：遍历列表求和。**题面：“程序先读取整数个数，再依次读取这些整数；起始代码已把它们保存到 `numbers` 列表。请在标记位置使用 `for number in numbers` 一类的遍历写法，把各数累加，最后只输出总和。没有数字时输出 `0`。”例如输入 `3, 2, 3, 5`（每个数字独占一行），输出 `10`。公开检查三个数和零个数；隐藏检查单个数、重复值、负数与不同长度列表。完成标准是无论输入顺序和数量如何，均逐项遍历并输出正确总和。诊断可区分未初始化累加变量、循环体缩进错误、漏算元素、在循环内重复输出。

三题统一使用“标准输入 → 标准输出”的小程序形式，公开和隐藏测试都通过不同输入运行同一份学生代码。隐藏测试只能覆盖题面已写明的规则，不通过未告知的特殊情况增加难度。PYB-03 的起始代码可以预先完成读取列表的步骤，使学生只需练习遍历和累加；三题均不包含参考实现。

每题任务包必须包含：题面与可观察完成标准、起始代码、技能 ID、公开测试、仅服务端可读的隐藏测试、客观评测规则、教师量规、示范错误样本。公开测试要帮助学生定位问题，隐藏测试只验证迁移与边界，不能把测试源码、敏感断言或标准答案传给学生或 Tutor。

三题的输入行数、允许的整数范围与输出格式须在任务包中固定并版本化。自动评测只产出“哪些要求通过、对应哪些技能证据”，暂不推算 0–100 掌握度；正式成绩仍由教师依据量规确认。

## 3. 借鉴参考产品后的界面边界

### 学生端

首屏只回答三个问题：**我要做什么、代码运行出了什么结果、下一步怎么改。**顶部保留课程/任务、保存状态、Run、Submit。桌面主体为可收起的任务说明栏、占主位的 Monaco 编辑器与底部输出/测试区、可收起的 Tutor 栏。导师展示与当前 Snapshot 绑定的观察、依据和一个可执行的下一步，并支持继续对话。

删除新版默认页上的 FAQ 预览、`faq_app.py` 专用按钮、重复阶段说明和没有证据来源的固定“老师指导”。保留教师真实消息，但与 AI 建议分开标识。首版调试能力为 stdout/stderr、测试差异、文件与行号跳转；断点调试器不列入首版。

### 教师端

保留“课堂”和“教学对话”两个主入口。课堂首屏优先显示待帮助学生、错误类型 Top N、技能证据不足点和完成情况；结论必须能点击下钻到学生运行与测试记录。对话可基于授权班级数据生成可交互图表，保留现有桑基、柱状、折线、表格与热力图能力，但图表类型由问题和数据决定。样本不足时显示样本数，不虚构精确掌握度。

完整版任务搭建器、跨课程比较、更多可视化种类、RAG、完整断点调试和多语言执行均不进入首版。教师可先选择并发布已校验的任务包，后续再做可视化任务编辑。

## 5. 下一阶段顺序与验收门槛

新版改造共六个阶段：本文件的阶段 01 为产品与任务基线，以下五步依次对应阶段 02–06。

1. **一题纵向闭环：**定义版本化任务包结构；让 PYB-01 完成加载、保存、Run 公开检查、Submit 隐藏检查、证据记录和教师下钻。验收时故意提交边界错误，学生只能看到可公开反馈。
2. **Runner 替换：**以现有执行协议为边界实现 Linux 可用的独立 Runner；同一 Snapshot 在旧/新执行器上比对结果。新 Runner 必须以非特权用户运行学生代码、限制资源与网络、隔离隐藏测试及服务密钥。
3. **四项职责与三题：**扩展 PYB-02/03，加入错误分类、技能证据、Tutor 分级提示和教学分析。成功、失败、超时与模型不可用都要留下可解释记录。
4. **师生端收敛：**按本文件的信息架构改界面；真实浏览器验证桌面和窄屏，确保键盘操作及旧结果/新代码的版本提示准确。
5. **云部署与试用：**正式认证、持久任务队列、容器部署、备份、并发与隔离验证；真实课堂试用数据脱敏后才用于成效说明。

阶段 01 不改变运行代码、依赖、数据库或已有演示数据。进入下一阶段前，三道实验的具体题面和量规需由任课教师核对；若暂无材料，可用本文件的虚构数据题目实现技术纵向切片，并明确标为示例课程。
